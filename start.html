내 출발점에서 시작하기

git 을 한 번도 써 보지 않은 학생부터 Claude Code 를 이미 쓰는 학생까지, 출발점에 따라 필요한 것이 다릅니다. 아래 세 질문에 답하고 자기 트랙을 따라갑니다. 어느 트랙이든 마지막은 같은 첫 연습 세션입니다.

§1세 가지 질문

  1. git 으로 commit 과 push 를 해 본 적이 있습니까?
  2. 터미널에서 명령을 입력하고 결과를 읽을 수 있습니까?
  3. AI 코딩 에이전트 (Kiro · Claude Code · Copilot agent mode · Cursor 등) 에게 파일을 고치게 해 본 적이 있습니까?

낯선 낱말이 나오면 용어 페이지를 봅니다. 「형상관리」 라는 말부터 번역어라 뜻이 잘 와닿지 않습니다.

§3트랙 2 — git 은 알고 에이전트는 처음

  1. 기초 B 로 웹 채팅 · IDE 에이전트 · CLI 에이전트의 차이를 봅니다.
  2. 템플릿으로 저장소를 만들고 clone 합니다 (2. 시작하기 §1). 커밋 이메일은 noreply 로 맞춥니다 (기초 A §3).
  3. Kiro 학생 등록 · Trust · 규칙 적재 확인을 합니다 (§2 · §5).
  4. 1. 개요 §2 에서 프롬프트를 왜 전부 남기는지 읽습니다.
  5. Pi 가 처음이면 기초 C 를 합니다.
  6. 첫 연습 세션을 합니다.

§4트랙 3 — 이미 에이전트를 쓰고 있다면

쓰던 도구를 그대로 써도 됩니다. 이 과목에서 달라지는 것만 확인합니다.

이 과목에서는확인할 것
규칙 원본은 AGENTS.md 하나CLAUDE.md 등 도구별 파일에는 @AGENTS.md 같은 참조만 둡니다. 쓰던 규칙이 있으면 AGENTS.md 로 옮깁니다
개인 전역 설정과 충돌하지 않게~/.claude/CLAUDE.md · ~/.codex/AGENTS.md · ~/.gemini/GEMINI.md · ~/.kiro/steering/ 에 자동 커밋 · 자동 승인 · 특정 trailer 같은 지시가 있으면 이 저장소에서는 과목 규칙이 우선하도록 정리합니다
프롬프트 전부를 회의록에 원문으로세션은 /session-close (Kiro · Claude Code) 로 닫고, 회의록의 「프롬프트 기록」 행 수가 내가 입력한 수와 맞는지 봅니다 (4. 세션 운영 §4)
구동 명령은 에이전트가 실행하지 않음구동 코드를 다루는 동안 자동 승인 모드 (Kiro Autopilot, Claude Code 의 자동 수락 · 권한 생략, Codex 의 전체 자동) 를 끕니다 (5. 실습 환경 §2)
docs/ai-usage.md 필수세션마다 한 줄, 「검토한 범위」 는 직접 씁니다
계획 → 승인 → 실행 → 결과 보고 → 승인 → 문서화평소보다 승인 관문이 많게 느껴질 수 있습니다. 이 관문에서 쓴 프롬프트가 사후 분석의 대상입니다 (1. 개요 §2)
여러 작업을 한꺼번에 맡길 때 (subagent · 병렬)무엇을 어느 작업에 맡겼는지 회의록에 적습니다. 그 작업에 준 지시문도 프롬프트 기록에 넣습니다

이어서 첫 연습 세션으로 과목 규칙이 내 도구에서 그대로 작동하는지 확인합니다.

§5첫 연습 세션 — 하드웨어 없이 한 바퀴

장치가 없어도 할 수 있는 작은 과제로 작업 순환 전체를 한 번 돕니다. 과제는 「starter 의 tools/check_log.py 가 정말로 문제를 잡는지 시험하기」 입니다 — 그 자체가 양성 대조 연습입니다.

  1. 세션을 엽니다.

    handoff.md 와 git log 를 읽고, 다음 작업을 계획으로 보고해 줘. 승인 전에는 착수하지 마. 오늘은 handoff 대신 이 작업을 할 거야: tools/check_log.py 를 시험할 50 Hz 가짜 로그 두 개 (정상 1 개, 중간 샘플 일부가 빠진 1 개) 를 만드는 스크립트를 tests/ 에 만들고, 두 로그를 check_log.py 로 검사해서 결과를 보고해 줘.

  2. 계획을 읽고 조건을 붙여 승인합니다. 예: 「계획 승인. 로그 파일은 logs/practice/ 에 두고, 결과는 표로만 보고해 줘.」
  3. 결과 보고를 받습니다. 정상 로그는 PASS, 결손 로그는 VOID 여야 합니다. 둘 다 PASS 라면 검사기나 가짜 로그가 틀린 것이니 이유를 묻습니다.
  4. 세션을 닫습니다. /session-close (또는 종료 요청 문장).
  5. 에이전트가 쓴 회의록을 검토합니다. 「프롬프트 기록」 의 행 수가 내가 입력한 프롬프트 수와 같은지, 원문이 그대로인지, 시각이 실측값인지 봅니다. 빠진 것이 있으면 고치고 커밋합니다.
  6. GitHub 에서 확인합니다. 회의록 · handoff · ai-usage 커밋이 올라왔는지 봅니다.

다음여기까지 하면 이 과목의 형상관리를 한 바퀴 경험한 것입니다. 그다음은 6. 주제별 가이드의 공통 단계 1 번 (센서 하나 읽기) 으로 실제 프로젝트를 시작합니다.
