4 · 세션 운영

세션 하나를 처음부터 끝까지

세션은 1~3 시간짜리 작업 단위입니다. 열 때 handoff 를 읽고, 닫을 때 에이전트가 회의록과 handoff 를 씁니다. 그 사이에 계획과 결과를 한 번씩 주고받습니다. 아래 프롬프트는 그대로 복사해 써도 되고 자기 말투로 바꿔도 됩니다. 어느 쪽이든 그 프롬프트는 회의록에 원문 그대로 남습니다.

§1세션 열기

handoff.md 와 지난 세션 이후의 git log 를 읽고, 다음 작업을 계획 (목표 / 단계 / 검증 방법) 으로 보고해 줘. 승인 전에는 착수하지 마.

에이전트가 할 일은 AGENTS.md §1-1 에 있습니다: git pull → 지난 세션 이후 커밋 전부 확인 (노트북 · Pi 양쪽) → handoff 정독 → 계획 보고. 「계속」 「진행」 처럼 짧게만 말하면, 에이전트는 handoff 의 다음 작업에 곧바로 들어가곤 합니다. 세션 첫 마디는 계획을 요구하는 문장으로 합니다.

§2계획을 받고 승인하기

좋은 계획 보고에는 네 가지가 있습니다.

목표
이 세션이 끝나면 무엇이 참이 되는지 (예: 「서보 각도 한계 검사가 보정표 변환을 쓴다」)
단계
순서가 있는 작업 목록. 하드웨어 실행 단계는 「학생이 실행」 으로 표시합니다
검증 방법
끝났음을 무엇으로 확인하는지 (테스트, 스윕, 로그 검사). 「확인한다」 만 있으면 다시 묻습니다
범위 밖
이번에 하지 않는 것. 진단 중 발견한 다른 문제는 여기로 갑니다

승인 · 반려는 짧고 분명하게 합니다. 조건을 붙여 승인할 때는 조건을 문장으로 씁니다. 「ㅇㅇ」 와 아래 문장은 둘 다 승인이지만, 나중에 프롬프트를 분석할 때 전혀 다르게 읽힙니다.

2 단계까지만 승인. 3 단계의 서보 실행은 내가 장치 옆에 있을 때 다시 보고해 줘.

§3결과 보고 받기

실험이나 측정이 끝나면 에이전트는 다음으로 넘어가기 전에 결과를 보고해야 합니다 (AGENTS.md §2-3). 보고에는 다음이 있어야 합니다.

  • 수치 표 — 조건 × 지표, 반복이 있으면 mean ± sd
  • 판정 — 사전등재한 판정 기준에 비추어
  • 무엇을 맞췄나 (정합 축) 와 실제 적용값 — 5. 측정 규율
  • 로그 무결성 결과 — PASS / VOID

결과가 코드 설명 끝에 한 줄로 묻혀 있거나, 보고 없이 다음 실험이 시작되었다면 멈춥니다.

다음 단계로 넘어가지 말고, 방금 측정의 결과만 표로 보고해 줘. 정합 축, 실제 적용값, check_log 결과를 포함해서.

§4세션 닫기 — 에이전트가 회의록을 씁니다

세션을 닫을 때는 Kiro · Claude Code 에서 /session-close 를 입력합니다. 다른 도구에서는 이렇게 요청합니다.

AGENTS.md §1-3 의 종료 절차대로 세션을 닫아 줘. 회의록의 프롬프트 기록에는 이번 세션의 내 프롬프트를 전부 원문 그대로 옮기고, 시각은 date 로 읽어.

그러면 에이전트가 회의록을 스스로 작성하고, handoff.md 를 덮어쓰고, docs/ai-usage.md 에 한 줄을 추가한 뒤 commit · push 합니다. 에이전트가 회의록을 자동으로 만들어 내는 과정을 직접 보는 것이 이 과목이 의도한 경험입니다. 그다음 학생이 검토합니다.

검토 항목확인 방법
프롬프트가 빠지지 않았나채팅 창을 위로 올리며 프롬프트 수를 세어 「프롬프트 기록」 표의 행 수와 맞춥니다. 짧은 「진행」 이 가장 잘 빠집니다
프롬프트가 고쳐지지 않았나요약 · 맞춤법 교정 · 존댓말 변환이 없는지 봅니다. 원문 그대로여야 분석할 수 있습니다
시각이 실측값인가「14:3x」 같은 자리표시나 지어낸 시각이 없는지, 첫 항목 시각이 세션 시작과 맞는지 봅니다
결정자가 있나「결정」 항목마다 결정자와 시각이 있는지, 에이전트가 정한 것이 「가정」 으로 분리되었는지 봅니다
수치에 출처가 있나회의록의 수치마다 로그 파일이나 실험 기록 경로가 있는지 봅니다

고칠 것이 있으면 직접 고치고 notes: review fixes for <회의록> 로 따로 커밋합니다. 에이전트가 무엇을 빠뜨렸는지는 그 자체로 기록할 가치가 있습니다 — docs/ai-usage.md 의 「검토한 범위」 에 적습니다.

대화 원본대화가 길어지면 에이전트가 앞부분을 요약해 버려 프롬프트를 옮기지 못할 수 있습니다. 이 경우 회의록에 「옮기지 못한 구간」 이 적혀야 합니다. 도구의 대화 내보내기 기능 (예: Kiro IDE 의 대화 내보내기) 으로 원본을 docs/sessions/ 에 보관해 두면 나중에 대조할 수 있습니다 — 이 과목에서는 선택이며, 보관 전에 비밀번호 · 토큰 · 개인정보를 확인합니다.

§5handoff.md

handoff 는 다음 세션의 단일 진입점입니다. 하나만 두고, 매번 덮어쓰고, 50 행을 넘기지 않습니다. 지난 기록은 git 이력과 회의록에 있습니다. 문체는 회의록과 같이 「~함」 체입니다.

§6회의록의 구성

세션마다 1 편, 파일 이름은 YYYY-MM-DD-HHMM-<주제>.md (HHMM = 세션 시작 시각) 입니다. 틀은 docs/meeting-notes/TEMPLATE.md 에 있습니다. 문체는 「~함」 체입니다.

  • 진행 — 항목마다 [HH:MM]. 사고는 「⚠ 사고 —」 로 시작하고 첫 이상 1 건의 시간순 경과를 적습니다. 이 항목이 규칙 개정의 근거가 됩니다.
  • 측정 — 측정 세션만. 런별 raw 표와 요약 표 (mean ± sd) 두 개. 서술 한 줄로 결과를 압축하지 않습니다.
  • 결정 / 미결 — 결정자와 시각. 에이전트가 정한 것은 「가정」.
  • 프롬프트 기록 — 그 세션의 학생 프롬프트 전부를 번호 · 시각과 함께 원문 그대로.
  • 논의 흐름 — 방향을 바꾼 프롬프트만 골라, 번호로 가리키며 「에이전트 응답 요지 · 이 프롬프트가 없었다면」 을 적습니다.

§7커밋

커밋 메시지는 무엇을 했나가 아니라 무엇이 되었나를 씁니다. 접두어로 종류를 표시합니다.

피할 것좋은 예
update codectrl: compute the derivative on the measurement so setpoint steps do not kick
fix bughw: route the safety limit check through to_mm() so both paths agree at the beam ends
add rulerules: void any log whose sample count misses rate x duration (r6)
meeting notesnotes: log-drop diagnosis and the sample-count identity
  • 접두어: ctrl sim hw test exp report notes handoff rules
  • 규칙 변경은 단독 커밋으로 합니다. 그림 · PDF 같은 생성물도 따로 커밋합니다.
  • Pi 에서 한 작업도 Pi 에서 커밋 · push 합니다. 기기를 옮기기 전에 반드시 push 합니다.
  • force-push 와 이력 재작성은 하지 않습니다. 회의록에 적힌 커밋 번호 (SHA) 가 모두 깨집니다.

§8AI 사용 기록

docs/ai-usage.md 는 필수입니다. 세션마다 한 줄: 날짜 · 도구와 모델 · 한 일 · 학생이 검토한 범위 · 회의록. 세션 종료 때 에이전트가 초안을 넣고, 「검토한 범위」 는 학생이 직접 고칩니다.

검토 범위 — 피할 것검토 범위 — 좋은 예
전부 검토함ctrl/pid.py 를 읽고 시뮬레이터 계단응답 3 개로 확인함
확인 완료표 2 의 수치 12 개를 logs/experiments/2026-11-12-*.md 와 대조함
문제 없음회의록 프롬프트 기록에서 P2 가 빠져 추가함. 데이터시트 「deadband 사양 없음」 을 원본 PDF 표 3 에서 찾아 정정함

커밋 trailer (예: Assisted-by: Kiro) 를 쓸지는 학생이 정해 AGENTS.md §9 에 적습니다. trailer 를 쓰든 안 쓰든 이 표는 채웁니다.

§9세션이 길어질 때

  • 새 세션이 더 싸고 정확합니다. 대화가 길어지면 에이전트는 자동 요약을 하고, 그때 세부와 프롬프트 원문이 빠집니다. 한 주제가 끝나면 /session-close 로 닫고 새 세션을 엽니다.
  • 크레딧 절약. 큰 파일 전체를 붙이지 말고 파일:행 으로 가리킵니다. 같은 질문을 반복하지 않도록 「확정 (재론 불요)」 를 유지합니다.
  • 다른 기기로 옮길 때 (노트북 ↔ Pi): 대화 기록은 따라오지 않습니다. handoff 를 push 하고 다른 기기에서 pull 합니다.
