2 · 시작하기

저장소를 만들고 에이전트가 규칙을 읽게 하기

자기 저장소를 템플릿으로 만들고, 쓰는 도구가 AGENTS.md 를 읽는지 확인하고, 회의록을 편하게 볼 뷰어를 준비하는 데까지가 이 페이지의 범위입니다. 도구 정보는 2026-10-05 에 각 도구의 공식 문서로 확인했습니다.

§1템플릿으로 저장소 만들기

clone · commit · push 가 처음이면 기초 A: git · GitHub 를 먼저 읽습니다.

  1. esd2026-starter 에서 Use this template → Create a new repository 를 누릅니다. 공개 범위와 지도교수 · 조교 초대는 강의 공지를 따릅니다.
  2. 노트북에 clone 하고, Raspberry Pi 에도 같은 저장소를 clone 합니다.
  3. AGENTS.md §0 「프로젝트 개요」 를 채우고, topics/ 에서 자기 주제 파일 하나를 골라 그 내용을 §8 에 붙여 넣습니다.
  4. rules: fill in project overview and topic rules 로 커밋하고 push 합니다. 이것이 규칙 r0 입니다.

§2Kiro 준비

학생 등록 — Kiro for Students

국민대학교는 Kiro for Students 대상 학교입니다. 인증하면 매월 1,000 credits 를 12 개월 동안 받습니다.

  1. Google · GitHub · AWS Builder ID 중 하나로 Kiro 에 가입합니다. 이때 계정에 학교 이메일 (@kookmin.ac.kr) 이 연결되어 있어야 합니다. 「Your organization」 로그인은 학생 프로그램에서 쓰지 않습니다.
  2. 계정 사용량 화면에 「You are eligible for Kiro Students」 배너가 뜨면 눌러 SheerID 인증을 합니다 (이름 · 생년월일 · 학교. 경우에 따라 학생증이나 재학증명서를 올립니다).
  3. 인증이 끝나면 신용카드 없이 혜택이 시작됩니다.

유의만 18 세 이상만 대상입니다. 혜택 기간에는 추가 크레딧을 살 수 없고, 남은 크레딧은 다음 달로 넘어가지 않습니다. 12 개월이 지나면 Free 등급이 됩니다. 약관상 학생 계정은 Free Tier 사용자로 간주되어, 기본 설정에서는 대화 내용이 서비스 개선에 쓰일 수 있습니다. 원하지 않으면 설정 → User → Application → Telemetry and Content 에서 끕니다.

처음 열 때 — Trust

Kiro IDE 로 저장소를 처음 열면 워크스페이스를 신뢰할지 묻습니다. Trust 를 눌러야 steering 파일이 적재됩니다. 누르지 않으면 규칙 일부가 적재되지 않은 채로 일하게 됩니다.

Kiro 가 읽는 파일

  • AGENTS.md — 저장소 루트의 파일을 설정 없이 항상 읽습니다. 그래서 Kiro 용으로 따로 복사할 필요가 없습니다.
  • .kiro/steering/*.md — Kiro 전용 보조 규칙입니다. 파일 첫 줄의 front matter 로 언제 적재할지 정합니다. AGENTS.md 의 내용을 여기에 되풀이하지 않습니다. 다른 도구는 이 폴더를 읽지 않으므로, 모든 도구가 지켜야 할 규칙은 AGENTS.md 에 둡니다.
---
inclusion: fileMatch
fileMatchPattern: ["hw/**", "**/*motor*", "**/*servo*", "**/*laser*"]
---

Supervised 모드와 권한

Kiro 의 기본값은 Autopilot (에이전트가 스스로 파일을 고치며 진행) 입니다. 구동기 코드를 다루는 동안에는 Supervised 로 바꿉니다 — 파일을 고칠 때마다 멈추고 변경 단위로 승인받습니다. 명령 실행 권한은 사용자 설정 (~/.kiro/settings/permissions.yaml) 에서 정합니다. 이 파일은 저장소 밖에 있으므로 각자 설정합니다: sudo 와 구동 스크립트 실행은 묻도록 (또는 거부하도록) 둡니다. 형식은 Kiro 권한 문서를 따릅니다.

Specs — 계획 먼저를 Kiro 방식으로

Kiro 의 Specs 는 .kiro/specs/<이름>/ 아래에 requirements.md → design.md → tasks.md 를 만들고 단계마다 승인을 받습니다. 이 튜토리얼의 「계획 보고 → 승인」 과 같은 구조입니다. 센서 드라이버, 제어기 구조처럼 며칠에 걸친 기능은 spec 으로 진행하면 계획이 파일로 남습니다. 요구사항은 EARS 형식으로 씁니다.

WHEN the servo command stays at a limit for more than STALL_TIMEOUT_S
THE SYSTEM SHALL return the servo output to neutral and log a stall event

참고Plan mode (Shift+Tab) 의 계획은 대화에만 남고 파일로 저장되지 않습니다. 계획을 남기려면 spec 을 쓰거나, 승인된 계획을 회의록에 옮깁니다.

Hooks (선택)

Hook 은 에이전트의 특정 시점 (세션 시작 · 종료, 파일 저장, 도구 실행 전후 등) 에 명령을 자동 실행합니다. Kiro IDE 1.0 부터 형식이 .kiro/hooks/<이름>.json 으로 바뀌었습니다. 파일 저장 trigger 는 에이전트가 바꾼 파일에만 반응합니다 — 사람이 편집기에서 고친 것에는 반응하지 않습니다.

{
  "version": "v1",
  "hooks": [
    {
      "name": "session-close-check",
      "description": "Before stopping, run the close-out checks from AGENTS.md section 1-3",
      "trigger": "Stop",
      "action": {
        "type": "agent",
        "prompt": "Before you stop: report whether the meeting note (with every prompt of this session, verbatim) is written, handoff.md is overwritten, docs/ai-usage.md has a new line, and everything is pushed. Fix anything missing first."
      }
    }
  ]
}

필드 구성은 Kiro hooks 문서를 따랐습니다. Hook 은 편의 기능입니다 — 규칙은 hook 이 없어도 지켜져야 합니다.

Kiro CLI (Raspberry Pi 4 에서 쓰려면)

기본 구성에서는 Pi 에 에이전트를 설치하지 않습니다 (5. 실습 환경 §1). Pi 4 (메모리 4 GB 이상, 64-bit OS) 에서 직접 쓰고 싶을 때만 설치합니다. Pi 3 B+ 는 메모리가 1 GB 라 권하지 않습니다.

curl -fsSL https://cli.kiro.dev/install | bash
kiro-cli login        # 브라우저가 없으면 URL 과 일회용 코드를 노트북 브라우저에서 입력
kiro-cli              # 대화 시작. /context show 로 적재된 규칙 파일 확인
  • 수업 기본 OS 는 32-bit 이므로 Kiro CLI 를 쓰려면 64-bit OS 를 따로 설치합니다 (기초 C §1). Pi 4 에서 illegal instruction 으로 멈춘다는 보고가 있으며, 그때는 설치 문서의 musl 빌드 (kirocli-aarch64-linux-musl.zip) 로 다시 설치합니다.
  • CLI 의 화면 모드에서는 sudo 처럼 입력을 기다리는 명령을 쓸 수 없습니다. GPIO · I2C · 카메라는 사용자 그룹 권한으로 해결합니다 (5. 실습 환경).
  • CLI 의 새 엔진 (V3) 은 아직 선택 사항 (--v3) 입니다. 기존 엔진은 fileMatch · manual steering 을 자동으로 적재하지 않습니다 — 그래서 꼭 필요한 규칙은 AGENTS.md 에 둡니다.
  • CLI 의 대화 기록은 Pi 안에 저장되어 노트북의 Kiro 와 공유되지 않습니다. 두 곳을 잇는 것은 handoff.md 와 git 뿐입니다.

§4웹 채팅만 쓸 때

구독 없이 ChatGPT · Claude · Gemini 웹 채팅만 쓰는 경우에도 같은 파일 체계를 씁니다. 다른 점은 학생이 파일을 옮겨 준다는 것입니다.

  1. 새 대화를 열 때마다 AGENTS.md 와 handoff.md 의 내용을 붙여 넣고, 「이 규칙을 따르고, 다음 작업을 계획으로 보고해 줘」 라고 시작합니다.
  2. 관련 코드 파일은 필요한 것만 붙여 넣습니다. 에이전트가 저장소 전체를 볼 수 없다는 점을 기억합니다.
  3. 제안받은 변경은 직접 파일에 반영하고 실행합니다. 결과 (로그 요약 · 오류 메시지) 를 다시 붙여 넣습니다.
  4. 끝낼 때 「오늘 내용으로 회의록 초안과 새 handoff.md 를 써 줘. 프롬프트 기록에는 이번 대화의 내 프롬프트를 전부 원문 그대로 옮겨 줘」 라고 요청하고, 검토한 뒤 직접 커밋합니다.

§5규칙이 적재되었는지 확인 — 양성 대조

「규칙 파일을 만들었다」 와 「에이전트가 그 파일을 읽었다」 는 다릅니다. 확인하려면 답을 이미 아는 질문을 합니다. 이렇게 결과를 미리 아는 입력으로 검사 도구 자체를 시험하는 것을 양성 대조라고 합니다. 이 튜토리얼 전체에서 반복해 나오는 방법입니다.

파일을 새로 열지 말고, 이미 받은 지시만으로 답해 줘. AGENTS.md §3 의 1 번 조항 제목은 무엇이야?

  • 파일 읽기 없이 「구동 명령은 사람 입회 하에」 라고 답하면 적재된 것입니다.
  • 파일을 열러 가거나, 모른다고 하거나, 그럴듯한 다른 답을 하면 적재되지 않은 것입니다 — §2 · §3 의 설정을 다시 확인합니다.
  • 규칙을 고친 뒤에도, 도구를 업데이트한 뒤에도 한 번씩 다시 묻습니다.

§6회의록 뷰어 — Obsidian

회의록 · handoff · 실험 기록은 모두 Markdown 파일이고 서로를 링크로 가리킵니다. 편집기에서 하나씩 여는 것보다 노트 뷰어로 저장소 폴더를 열면 링크와 백링크를 따라가며 훨씬 편하게 읽을 수 있습니다. 무료로 쓸 수 있는 Obsidian 을 권합니다.

  1. Obsidian 을 설치하고 Open folder as vault 로 노트북의 저장소 폴더를 엽니다. Obsidian 이 만드는 .obsidian/ 폴더는 starter 의 .gitignore 에 들어 있어 커밋되지 않습니다.
  2. 설정 → Files and links 에서 아래처럼 바꿉니다.
    • Use [[Wikilinks]] 끄기 — 표준 Markdown 링크로 저장되어 GitHub 에서도 링크가 깨지지 않습니다
    • New link format → Relative path to file
    • Automatically update internal links 끄기 — 파일 이름을 바꿀 때 여러 회의록이 조용히 수정되는 것을 막습니다
    • Detect all file extensions 켜기 — .py · .csv 도 파일 목록에 보입니다
    • Excluded files 에 .venv · logs/raw 추가
  3. 오른쪽 패널의 Backlinks 로 「이 실험 기록을 가리키는 회의록」 을, Graph view 로 회의록 · 실험 · 규칙의 연결을 봅니다. 검색창에 "프롬프트 기록" 을 넣으면 모든 회의록의 프롬프트 표를 모아 볼 수 있습니다 — 회고 때 유용합니다.

유의에이전트가 회의록을 쓰는 동안에는 같은 파일을 Obsidian 에서 편집하지 않습니다. 검토 후 고칠 것이 있으면 세션 종료 커밋이 끝난 뒤 고치고 따로 커밋합니다.

다른 방법: Kiro · VS Code 의 Markdown 미리보기 (Ctrl/Cmd + Shift + V), 또는 GitHub 웹에서 저장소를 열어 보기.
