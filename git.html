기초 A · git · GitHub

git 과 GitHub — 기록을 쌓고 기기 사이로 옮기기

git 을 한 번도 써 보지 않았다면 이 페이지부터 읽습니다. 이 과목에서 git 은 두 가지 일을 합니다. 하나는 기록 — 무엇을 언제 왜 바꿨는지가 남습니다. 다른 하나는 운반 — 노트북에서 고친 코드를 Raspberry Pi 로, Pi 에서 잰 로그를 노트북으로 옮깁니다.

§1낱말 다섯 개

저장소 (repository)
git 이 기록을 관리하는 폴더입니다. 폴더 안에 숨은 .git 폴더가 있으면 저장소입니다.
커밋 (commit)
그 순간의 파일 상태를 찍어 둔 스냅샷입니다. 누가 · 언제 · 왜 (메시지) 가 함께 남고, 3f9c2a1 같은 고유 번호 (SHA) 가 붙습니다. 회의록이 이 번호로 커밋을 가리킵니다.
원격 (remote)
인터넷에 있는 같은 저장소입니다. 이 과목에서는 GitHub 에 있는 내 저장소입니다.
push
내 커밋을 원격으로 올립니다.
pull
원격의 새 커밋을 내 쪽으로 받아 옵니다. 처음 한 번 저장소 전체를 받아 오는 것은 clone 이라고 합니다.

§2세 장소와 네 동작

  • add — 고친 파일 중 다음 커밋에 넣을 것을 고릅니다. 고른 것만 커밋됩니다.
  • commit — 고른 변경을 메시지와 함께 스냅샷으로 남깁니다. 아직 내 컴퓨터 안에만 있습니다.
  • push — 커밋을 GitHub 로 올립니다. 이제 다른 기기에서 받을 수 있습니다.
  • pull — 다른 기기가 올린 커밋을 받아 옵니다. 일을 시작할 때 항상 먼저 합니다.

§3설치와 첫 설정

Git 설치

환경방법확인
Windowsgit-scm.com 에서 Git for Windows 를 설치합니다 (기본 선택 그대로)PowerShell 에서 git --version
macOS터미널에서 git --version 을 입력하면 설치 안내가 뜹니다 (Command Line Tools)git --version
Raspberry Pi OS보통 이미 들어 있습니다. 없으면 sudo apt install gitgit --version

GitHub 계정과 이메일 공개 범위

  1. github.com 에서 계정을 만들고, Settings → Emails 에 학교 이메일을 추가합니다. 학생 인증을 하면 Copilot Student 도 받을 수 있습니다 (2. 시작하기 §7).
  2. 같은 화면에서 Keep my email addresses private 를 켭니다. 그러면 숫자+아이디@users.noreply.github.com 형태의 대신 쓸 주소가 보입니다.
  3. 커밋에 남는 이름과 이메일을 설정합니다. 이메일은 위의 noreply 주소를 씁니다 — 커밋의 이메일은 저장소를 공개하면 누구나 볼 수 있습니다.
git config --global user.name  "홍길동"
git config --global user.email "12345678+gildong@users.noreply.github.com"
git config --global init.defaultBranch main

GitHub 로그인 (인증)

  • 노트북 — Kiro (또는 VS Code) 에서 처음 push 할 때 「Sign in with GitHub」 창이 뜨면 브라우저로 로그인합니다. 터미널을 쓴다면 GitHub CLI 를 설치하고 gh auth login 을 한 번 실행합니다.
  • Raspberry Pi — 화면 없이 SSH 로 쓰므로 SSH 키를 씁니다. Pi 에서 키를 만들고, 공개키를 GitHub 의 Settings → SSH and GPG keys 에 붙여 넣습니다.
ssh-keygen -t ed25519 -C "pi"     # 엔터 세 번 (비밀번호 없이도 됩니다)
cat ~/.ssh/id_ed25519.pub          # 출력된 한 줄을 GitHub 에 등록
ssh -T git@github.com              # "Hi 아이디!" 가 나오면 성공

§4첫 저장소와 첫 커밋

  1. GitHub 에서 esd2026-starter → Use this template → 이름을 정하고 저장소를 만듭니다.
  2. 노트북: Kiro 의 시작 화면에서 Clone repository 를 고르고 저장소 주소를 붙여 넣습니다 (터미널이라면 git clone <주소>).
  3. AGENTS.md §0 의 「결정자」 줄에 자기 이름을 씁니다.
  4. Source Control 패널 (왼쪽 막대의 갈래 모양 아이콘) 에서 바뀐 파일 옆 + (add) → 메시지 입력 → Commit → Sync / Push.
  5. GitHub 웹에서 저장소를 새로 고쳐 커밋이 올라왔는지 확인합니다.
git status                     # 무엇이 바뀌었나
git add AGENTS.md              # 다음 커밋에 넣기
git commit -m "rules: fill in the decider line"
git push                       # GitHub 로 올리기
git log --oneline -3           # 최근 커밋 3 개 보기

§5이 과목의 하루 흐름

어디서순서
노트북git pull → 에이전트와 코드 수정 → commit → git push
Pi (SSH)git pull → 실행 · 측정 → git add logs/ → commit → git push
노트북git pull → 로그 분석 → 세션 종료 (/session-close 가 회의록 · handoff 를 commit · push)

기기를 옮기기 전에 반드시 push 합니다. 한쪽에서 push 하지 않은 커밋은 다른 쪽에서 보이지 않고, 그 상태로 같은 파일을 양쪽에서 고치면 충돌이 납니다.

명령언제
git clone <주소>처음 한 번, 저장소를 내려받을 때
git pull일을 시작할 때마다
git status무엇이 바뀌었는지 볼 때 (가장 자주 씁니다)
git diff바뀐 내용을 줄 단위로 볼 때 — 커밋 전에 봅니다
git add <파일>다음 커밋에 넣을 파일을 고를 때
git commit -m "..."고른 변경을 기록할 때
git push기록을 GitHub 로 올릴 때 — 기기를 옮기기 전에 반드시
git log --oneline지난 커밋 목록을 볼 때 — 세션 시작 때 handoff 와 대조합니다

§6에이전트에게 git 을 맡길 때

  • 에이전트는 commit · push 를 대신할 수 있습니다. 세션 종료 절차도 에이전트가 커밋합니다. 다만 무엇이 커밋되는지는 학생이 봅니다 — 「커밋하기 전에 git diff 요약을 보여 줘」 라고 요청합니다.
  • .env, 비밀번호, 큰 영상 파일이 커밋되지 않는지 봅니다. starter 의 .gitignore 가 대부분을 막지만, 새 종류의 파일은 직접 확인합니다.
  • 커밋 메시지는 4. 세션 운영 §7 의 형식을 따릅니다.
  • 에이전트가 --force 가 들어간 명령 (git push --force, git reset --hard) 을 제안하면 실행하지 않고 이유를 묻습니다. 기록이 지워질 수 있습니다.

§7문제가 생겼을 때

증상뜻대응
push 가 rejected (fetch first)다른 기기가 먼저 올린 커밋이 있습니다git pull 을 먼저 하고 다시 push 합니다
CONFLICT · 파일에 <<<<<<< 표시같은 줄을 양쪽에서 고쳤습니다표시된 부분을 직접 정리하거나, 에이전트에게 「충돌 상황을 설명하고 해결 계획을 보고해 줘」 라고 요청합니다. 정리 후 add · commit
고친 파일을 원래대로 되돌리고 싶은 경우아직 커밋하지 않은 변경입니다git restore <파일> — 그 파일의 변경이 사라지므로 먼저 git diff 로 확인합니다
비밀번호를 실수로 커밋한 경우push 했다면 이미 노출된 것으로 봅니다비밀번호부터 바꿉니다. 이력에서 지우는 것은 그다음 문제이며, 지도교수 · 조교와 상의합니다
무슨 상황인지 모르는 경우—멈추고 git status 출력을 그대로 에이전트나 조교에게 보여 줍니다. 모르는 채로 명령을 더 치지 않습니다

§8계보 — SCCS · RCS · CVS · SVN · git

git 은 버전 관리 도구의 세 번째 세대입니다. 앞 세대의 한계가 다음 세대를 낳았습니다.

세대대표 도구 (처음 나온 해)방식한계
로컬 · 파일 단위SCCS (1972) · RCS (1982)파일 하나하나의 이력을 한 컴퓨터 안에 둡니다여러 사람 · 여러 기기가 함께 쓰기 어렵습니다
중앙 집중CVS (1986) · Subversion (SVN, 2000)서버 하나가 이력을 갖고, 각자 서버에서 받아 고친 뒤 서버에 커밋합니다. SVN 은 CVS 를 대체하려고 만들어져, 여러 파일의 변경을 한 번에 기록하는 등 CVS 의 약점을 고쳤습니다서버에 연결되지 않으면 커밋할 수 없고, 서버가 멈추면 모두 멈춥니다
분산Git (2005) · Mercurial (2005)clone 하나하나가 전체 이력을 갖습니다. 오프라인에서도 커밋하고, 나중에 push 로 합칩니다— 이 과목의 노트북과 Pi 가 각자 전체 이력을 갖는 것이 이 방식입니다

GitHub (2008) 은 버전 관리 도구가 아니라 git 저장소를 웹에서 공유하고 협업하게 해 주는 호스팅 서비스입니다. git 은 GitHub 없이도 쓸 수 있습니다.
