기초 B · AI 도구의 형태

웹 채팅, IDE 에이전트, CLI 에이전트

같은 AI 모델이라도 어떤 형태로 쓰느냐에 따라 할 수 있는 일이 다릅니다. 핵심 차이는 AI 가 무엇을 볼 수 있고, 무엇을 직접 할 수 있느냐입니다. 이 차이를 알면 어느 도구를 언제 쓸지, 무엇을 조심할지가 정해집니다.

§1세 가지 형태

웹 채팅IDE 에이전트CLI 에이전트
예ChatGPT · Claude · Gemini 웹사이트Kiro IDE · Cursor · VS Code 의 Copilot agent modeKiro CLI · Claude Code · Codex CLI · Gemini CLI · Copilot CLI

세 형태 모두 이 과목의 기록 요구사항 (규칙 · handoff · 회의록의 프롬프트 기록 · AI 사용 기록) 은 같습니다. 다른 것은 그 기록을 누가 옮기느냐입니다 — 웹 채팅에서는 학생이, 에이전트에서는 에이전트가 옮기고 학생이 검토합니다.

§3무엇을 고르나

상황추천
git · 터미널이 처음인 경우Kiro IDE. 파일 변경과 git 을 화면으로 볼 수 있습니다
개념을 묻거나 오류 메시지의 뜻을 알고 싶은 경우웹 채팅도 충분합니다. 답을 코드에 반영했다면 그 대화도 프롬프트 기록에 옮깁니다
코드를 만들고 고치는 대부분의 작업IDE 에이전트
Pi 에 SSH 로 접속해 센서 · 카메라를 계속 시험하는 경우Pi 4 라면 CLI 에이전트도 가능합니다. Pi 3 B+ 는 노트북의 IDE 에이전트 + SSH 실행
이미 Claude Code · Codex 등을 잘 쓰는 경우그대로 써도 됩니다. 트랙 3 체크리스트만 확인합니다

§4어느 형태든 같은 네 가지 개념

컨텍스트
AI 가 지금 한 번에 볼 수 있는 글입니다 — 규칙 파일, 연 파일, 지금까지의 대화. 컨텍스트에 없는 것은 모릅니다. 그래서 규칙 파일이 적재되었는지 확인합니다.
승인 모드
에이전트가 파일을 고치거나 명령을 실행하기 전에 묻는지 정하는 설정입니다. Kiro 의 Supervised / Autopilot, Claude Code 의 권한 모드, Codex 의 승인 설정이 모두 이것입니다. 구동 코드를 다룰 때는 묻는 쪽으로 둡니다.
세션과 요약
대화가 길어지면 앞부분이 요약 (compaction) 되어 세부와 프롬프트 원문이 빠집니다. 주제가 끝나면 세션을 닫고 새로 엽니다.
비용 단위
도구마다 크레딧 · 요청 수 · 토큰으로 셉니다. 긴 대화, 큰 파일, 반복 질문이 많이 씁니다 (2. 시작하기 §7).

§5형태별 흔한 함정

형태함정대응
웹 채팅보지 못한 파일의 내용을 그럴듯하게 지어내 답합니다관련 파일을 실제로 붙여 넣고, 「붙여 넣지 않은 파일은 추측하지 마」 라고 말합니다
웹 채팅대화가 저장소 밖에 남아 기록이 끊깁니다세션 끝에 프롬프트를 회의록에 옮깁니다 (2. 시작하기 §4)
IDE 에이전트Autopilot 으로 여러 파일을 한꺼번에 고쳐 나갑니다계획 승인 후 착수하게 하고, 구동 코드는 Supervised 로 둡니다
CLI 에이전트명령을 연달아 실행하며 결과를 요약만 보고합니다명령 실행 전에 묻는 모드로 두고, 결과는 표로 보고받습니다 (4. 세션 운영 §3)
모든 형태틀린 것을 자신 있게 말합니다답을 아는 질문으로 시험하고 (양성 대조), 원본을 직접 열어 봅니다
